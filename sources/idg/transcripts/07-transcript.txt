lot of ground. Let's bring it all together. Product thinking is a discipline of asking better
questions before reaching for solutions. We started with why. The five whys exercise helps peel back
problems to find out what's actually driving it. From there, we crafted a clear problem statement
using the four C's framework. Clarity, consequence, cause, and confirmation. One statement, four
dimensions, still no solutions yet. With the problem defined, we then set useful metrics, smart
ones. We defined leading and lagging indicators to find the right ones to track and use the value
cost ratio to assess returns on investment. We assess risk and scale. Identify your biggest risk
early, find the lowest way to test it, start with a proof of concept, learn, then scale what works.
Finally, we spoke about the 11 stars framework to help think about what a good user experience looks
like. If there are three things to remember, let them be these. We want to move from solutions to
problems. Start with what's broken, not what technology is available. We want to move from outputs
to outcomes. A website with five buttons is an output. More citizens completing transactions is the
outcome. We want to move from big bang to stage delivery. Do the skateboard before you do the car.
Grab Amazon, Netflix. None of them started with the full vision we see today. They each solved one
problem for one group of people exceptionally well. That's the standard we're aiming for too. We now
have the frameworks. The five whys, the four C's, smart metrics, value cost ratio, and a staged
approach to scaling. Take one initiative you're working on. Apply them. That's product thinking in
practice.
